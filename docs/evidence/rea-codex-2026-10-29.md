## Native agent-to-agent features (all in-process; none reachable from outside)

- **Multi-agent V2** (`core/src/tools/handlers/multi_agents_v2/*`, tool choice in
  `core/src/tools/spec_plan.rs`): `spawn_agent`, `send_message`,
  `followup_task`, `interrupt_agent`, `list_agents`, `wait_agent`; no
  `close_agent` or `resume_agent`. Agents are addressed by path (`/root/a/b`).
  V2 is chosen per model by `multi_agent_version_for_model`; this machine's
  `~/.codex/models_cache.json` says `v2` for 8 of 11 models. V1 (`send_input`,
  `close_agent`, `resume_agent`) still exists. Whether V2 is active in a live
  session was not run.
- **What a receiver sees:** inter-agent mail is a first-class
  `ResponseItem::AgentMessage{author, recipient, content}`
  (`protocol/src/protocol.rs:926-1010`), rendered as `Message Type:
  MESSAGE|NEW_TASK|FINAL_ANSWER|CHANNEL_POST … Sender: <path>`. Model-sent
  payloads are encrypted unless the call source is `DirectPlaintextMessage`.
  **parity.md says the model-visible input is plain `UserInput`: that holds for
  `send_input` and the desktop path, not for V2.**
- **Typed completion:** `AgentStatus` is PendingInit, Running, Interrupted,
  Completed(msg), Errored(msg), Shutdown or NotFound (`protocol.rs:1932`). On a
  child's terminal turn the parent gets a `FINAL_ANSWER` with
  `trigger_turn=false`, so it is queued and does not wake an idle parent
  (`core/src/agent/control/completion.rs`).
- **Message board** (`ext/agent-message-board`): nine tools, `Feature::AgentMessageBoard`
  under development and off by default, and it also needs MultiAgentV2.
- **Approvals:** `approvals_reviewer` is `user` or `auto_review` (the Guardian
  sub-agent). No approval is routed to a parent agent. `PermissionRequest` and
  `SubagentStop` hooks are the Claude-like analogues.
- **Goals:** per thread, in `~/.codex/goals_1.sqlite`; not a shared task list.

## Unchanged and relevant to Magi

- `turn/start`, `turn/steer`, `thread/inject_items` and `thread/queue/*` refuse a
  V2 sub-agent ("direct app-server input is not allowed for multi-agent v2
  sub-agents"); `thread/list.canAcceptDirectInput` reports it, and Magi already
  filters on it (`src/codex-adapter.mjs:58`). Identical at 0.160.1.
- The app-server methods Magi uses are unchanged between 0.160.1, 0.163.0 and
  0.165-alpha, by schema and source diff (the 0.160.1 binary was not available).
  `turn/start` gains `parentTurnId` and `rootTurnId`; `multiAgentMode` is deprecated.

## Changed in the desktop: the app-tools pipe

- Read in `main-CP9z2iYn.js` (26.1023), offset about 347059:
  `nativePipeDirectory: process.platform==="win32" ? "\\\\.\\pipe\\codex-app-tools" : "/tmp/codex-app-tools"`.
  The browser-use directory is separate (`Di=e=>e==="win32"?"\\\\.\\pipe\\codex-browser-use":"/tmp/codex-browser-use"`, offset about 77471).
  The 26.1013 report found them sharing the browser-use prefix.
- Magi's `probeAppToolsPipe` listed only `codex-browser-use-*`. Fixed in this
  commit to list both (`APP_TOOLS_PIPE_PREFIXES`, `src/transport.mjs`), with a
  test in `test/steer.test.mjs` that fails on the old behavior.
- `tools/call` now requires `callerSource`, `callId`, `namespace`, `threadId`,
  `tool`, `turnId`; the plugin's `server.mjs` fills them from `_meta`, which Magi
  sends. Sender provenance is recognised only for `codex_app`/`codex_tui`
  `send_message_to_thread` and `cloud_threads` `send_message` outputs
  (`sender_context.rs`), so a plain Magi header is not read as a delegation.
- **Not established:** the actual pipe name at runtime (the desktop was not
  running), and whether Magi's primary path (parsing the app-server command line)
  still sees the config on 26.1023.
